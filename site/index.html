For Revit and AutoCAD workstations

Remove the Digital Dead Load.

Reclaim storage, reduce system clutter, and keep your engineering workstation running efficiently.

In structural engineering the dead load is the permanent weight a structure carries. DeadLoad removes the dead load Autodesk products leave on Windows workstations, and keeps the records worth keeping.

Features

Less overhead. More capacity.

A transparent Windows cleanup utility that helps identify and remove unnecessary files without putting engineering work at risk.

Reclaim storage

Removes temp files, web caches, crash reports and old installer logs past their age limits, and compresses Revit journals into monthly archives.

Clear visibility

Every item decision goes to the run log with the rule behind it. Report-only mode plans every category and changes nothing.

Configurable by policy

Every setting has a Group Policy template. Policy wins over local settings, which win over the shipped defaults, and each effective value shows its source.

Measured results

The defaults come from measurements on seven engineering workstations. Space recovered is counted from confirmed deletions, not estimated.

How it works

Analyze, review, clean.

DeadLoad runs unattended as SYSTEM from its own scheduled tasks, so no one has to remember to run it. You decide how much it may do before it does anything.

  1. Analyze

    A report-only run scans every enabled category and plans what it would delete, compress or keep, and why. It changes nothing.

  2. Review

    Read the plan before anything is removed: the run log names the rule behind each decision, and users see the last report in the tray app. Keep report-only on for a pilot week.

    An interactive review window for a user's own files In development

  3. Clean

    As SYSTEM: weekly maintenance (Sunday 03:00 by default), a daily disk pressure check that also runs on low-disk events, and an on-demand task users may start but not change. Users can clean their own temp files from the tray without admin rights.

What it examines

Built-in categories, with their limits.

A category ships enabled only when its paths were measured on real workstations. Each one has a risk tier that decides how a user's cleanup review will offer it: Routine files programs recreate or no longer need, selected by default; Review offered but not selected, since removing them can cause reprocessing or a download; Restricted never offered to users, left to the scheduled runs as policy configures.

Safety and transparency

Built to run as SYSTEM on production workstations.

Review before delete

Report-only mode and -WhatIf produce the full plan and change nothing. Run a pilot in report-only first.

Protected data types and folders

Never acted on: *.rvt *.rfa *.rte *.rft *.dwg *.dwt *.dws *.dxf *.bak *.nwd *.nwf *.nwc *.ifc *.pdf. Never entered: Documents, Desktop, OneDrive, and Autodesk Desktop Connector, ACC Docs and BIM 360 workspaces.

Process guard

While a user runs Revit, AutoCAD, Navisworks or DWG TrueView, DeadLoad skips that user's Autodesk categories. Locked files are skipped, and every file is checked again right before it is acted on.

No reparse points, no network

Junctions, symbolic links, mount points and cloud placeholders are never traversed or deleted, at any depth. The engine makes no HTTP calls; its targets ship in the package and nothing is downloaded at run time.

Logs and events

Each run writes a log naming the rule behind every decision, a JSON report a monitoring tool can read, and Windows events under the source DeadLoad (Application log).

Open source

Every line is on GitHub under GPL-3.0, including the safety tests that run on Windows PowerShell 5.1 and PowerShell 7.

Deletion is permanent. DeadLoad has no quarantine and no undo. What it deletes is gone, so it acts only on items past their limits, never on protected data, and logs each one.
For IT administrators

One package, one policy, nothing to babysit.

Group Policy

ADMX and ADML templates cover every setting: machine policy for the engine and the tray, user policy for the tray. Get-DeadLoadConfiguration -Trace shows each effective value and whether it came from policy, a local setting or the default.

Open the policy generator or read the recommended policy.

Chocolatey

Install, upgrade and uninstall need no restart. Parameters: /NoTray, /ReportOnly, /InstallAdmxLocally, and /PurgeData on uninstall.

Signed

The build signs every script, module, data file and binary when Authenticode signing is configured. A signed engine refuses to run when a file changed after signing.

Monitoring

Alert on event 1001 at Error, 2002 (pressure target not reachable), 3000 (run error) and 3003 (integrity check failed), and on a stale last-run.json.

Install

Get DeadLoad

No public release yet. DeadLoad is pre-release. Build the Chocolatey package from source and install it from your own feed or folder. Try it on a test machine first.

1. Build

git clone https://github.com/DailenG/DeadLoad.git
cd DeadLoad
pwsh -NoProfile -File build\Build.ps1

Needs PowerShell 7, the .NET 8 SDK (for the tray) and Chocolatey (to pack). Without signing configured the build is an unsigned development build and says so.

2. Install

choco install deadload --source <folder or feed> -y --params "'/ReportOnly'"

Runs on Windows 10 21H2 or later and Windows 11, with Windows PowerShell 5.1 and .NET Framework 4.8. Full steps: OPERATIONS.md.
